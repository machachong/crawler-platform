## 预检

不停止容器，不构建，不改 Nginx。

目录属主是 root，用 root 执行。不要改 `/usr/bin/python3`，也不要长期修改 PATH。主机默认 `python3` 可以仍是 3.6。脚本依次尝试 `PYTHON_BIN`、`python3.11`、`python3.10`、`python3.9`、`python3`，选用 3.9 或更新的解释器；都没有就在预检阶段失败。

```bash
cd /home/workspace/crawler-platform
jobs/deploy.sh --preflight-only
```

输出必须同时满足，否则停止，不要部署：

| 项 | 必须看到 |
| --- | --- |
| 项目 | `crawler-platform` |
| 工作目录 | `/home/workspace/crawler-platform` |
| 数据库卷 | `crawler-platform_postgres_data` |
| 网络 | `crawler-platform_default`（若不是这个名字，输出里的名字必须和现有 db 容器一致） |
| 端口 | `api 8010->8000, db 5433->5432, redis 6380->6379` |
| 不发布 | `8000 5432 6379 3000` |
| db / redis 镜像 | 以本次预检打印的现网镜像为准，结束时必须仍是这一对完整 ID。不使用早前手写前缀 |
| Compose | 打印实际版本。旧版本可以继续，不要为此升级 |

预检成功后看 `jobs/state/compose.runtime.yml`：只有上述三个主机端口，卷和网络都是 `external`，没有 `web`。部署命令只使用这一个文件，并显式带上检测到的项目名，忽略环境里的 `COMPOSE_PROJECT_NAME` 和 `COMPOSE_FILE`。

若项目名或卷名与上表不同，脚本会失败并打印实际值。先和备份核对。确认就是现有库之后，才可以设置 `CRAWLER_EXPECT_PROJECT` 和 `CRAWLER_EXPECT_VOLUME` 再预检。不要改完预期后直接部署到一个新卷。

## 部署当前目录

这次要发布的是已经在服务器上的 main（`cfa197d`）加上刚装上的脚本。**先不要运行** `update-from-github.sh`，否则会再从 GitHub 拉 main，而本变更还没进 main。

```bash
jobs/deploy.sh
```

脚本会：构建 `api/Dockerfile.deploy`（Debian 12 bookworm，Python 3.11，apt 超时 30 秒、重试 3 次），停止 api/worker/scheduler，运行 `python scripts/migrate_v2.py`，再启动。`db` 和 `redis` 使用 `--no-recreate`。健康检查必须是 `http://127.0.0.1:8010/api/v1/health` 里 `status=healthy` 且 `database=true`，否则退出码非 0。静态文件只用 `npm ci` 构建，并只写入 `/var/www/zhengaihe/crawler`。

不修改这两份 Nginx，也不假设 `/etc/nginx/conf.d/crawler.conf`：

- `/etc/nginx/sites-enabled/crawler.conf`
- `/etc/nginx/conf.d/zhengaihe-qingji1.conf`

不碰 qingji 的 8000、`/member`、`/homepage`。不执行 `docker compose down`、不删除卷、不 `volume prune`。成功后只清理悬空镜像。要求工作目录和 Docker 数据盘至少有 3072MB 可用。

`jobs/start-backend.sh` 等于 `jobs/deploy.sh --start-only`：不构建、不迁移，只按现有镜像启动，并做同样的端口和卷检查。

## 以后从 GitHub 更新

本变更进入 main 之后：

```bash
jobs/deploy.sh --update --ref main
```

它会先预检，拉取并核对完整 SHA，再停止 api/worker/scheduler，然后备份代码、写入文件、构建和迁移。`db`/`redis` 仍不重建。单独的 `jobs/update-from-github.sh` 在应用正在运行时会拒绝，因为 `./api` 挂进了容器。

固定某次提交：

```bash
jobs/deploy.sh --update --sha <40位SHA>
```

成功时打印 `已固定修订:` 和完整 SHA。记录写在 `jobs/state/REVISION`。代码备份在 `jobs/state/backups/`，最多 2 份，不含 `.env`。

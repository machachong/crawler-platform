# P1 任务管理与持续采集升级说明

日期：2026 年 11 月 5 日

## 本轮能力

- 任务中心支持名称、URL、标签搜索，以及状态、域名、创建日期筛选；每页 12 个任务，翻页、刷新和离开后返回保留当前账号的筛选条件。管理员查看全部任务与负责人，成员只查看自己的任务。
- 每次执行有独立运行 ID、序号、触发来源和配置快照，记录模型、页面数、Token、排队与阶段耗时。重跑保留旧结果；可切换历史并导出 JSON、CSV、Markdown、HTML。
- 每天、每周指定时间执行，可选择北京时间或 UTC，支持暂停和恢复。运行重叠时跳过本期并记录原因，停机后只补最近一期。
- 队列消息携带运行 ID，Worker 原子认领；重复消息和旧一轮消息不会重复执行或污染新结果。提交运行后、投递前进程退出的记录，由调度服务恢复投递。
- 创建前可先试跑 1 页，使用相同提示词和字段规则。试跑是独立任务，不启用周期调度，正常计入 AI 用量。
- 模板由服务端管理，支持内置模板、账号私有模板和版本保留。修改模板不影响已经创建的任务。
- 可定义扁平 JSON 字段：文本、数字、布尔值、ISO 日期、数组及必填规则。校验失败保留生成结果与具体原因，不作为合格内容发布。
- 修改提示词后可复用正文重新提取；失败页面可单独重试，重新抓取下载失败的页面，只为失败的 AI/校验结果重新提取，保留成功结果与原失败记录。
- 单次运行可设 Token 预算，长文分段同样检查。供应商返回用量后计量，达到阈值停止后续请求；已发出的请求可能超过阈值，页面显示实际返回值。
- 调度服务有心跳状态；计划启用而服务不在线时结果页显示提示。任务中心显示近 7 天创建的运行用量，运行详情显示分阶段耗时。
- 用户管理仍只有管理员可见。公开链接保持 `https://www.zhengaihe.top/crawler/<hashid>`，重跑不覆盖已发布快照。

## 数据兼容

本次新增表并补齐任务查询索引，不删除或改变旧 `tasks`、`crawl_results` 和 `published_pages` 的列。新表包括运行记录、调度计划与事件、模板与版本、服务心跳。

`crawl_results` 保持为最新结果缓存；运行结束时，完整结果写入对应 `task_runs.snapshot`，历史导出从快照读取。当前方案会额外保存最新结果的一份快照，后续可按数据规模迁移到按 run 分区的结果表。

旧任务通过迁移脚本归档当前状态；无法恢复升级前已被清空的更早结果。旧配置中的 `daily` 不会自动启动周期采集，需要在界面明确保存新计划。历史导入不推测原本没有记录的阶段耗时。

## 本地升级

先备份数据库，并让旧 Worker 中的任务结束或停止，避免新旧版本同时写入。仓库根目录执行：

```powershell
.venv/Scripts/python.exe api/scripts/migrate_v2.py
```

脚本可重复执行。重启 API、前端和 Celery Worker，并另开终端启动调度进程：

```powershell
.venv/Scripts/python.exe api/scripts/scheduler.py
```

调度进程每 30 秒检查一次到期计划，使用与 API 相同的 `DATABASE_URL`、`REDIS_URL`。实际采集仍由 Worker 执行，关闭网页不会停止计划。

## Docker 升级

先备份数据库并结束或停止旧版本正在执行的任务，再依次执行：

```powershell
docker compose build api worker scheduler web
docker compose stop worker scheduler
docker compose run --rm api python scripts/migrate_v2.py
docker compose up -d api worker scheduler web
```

Compose 已加入独立 scheduler 与 API 健康检查。不要执行 `docker compose down -v`，数据库卷需要保留。外部部署如果只更新 API 和 Worker，必须同时增加 scheduler 服务，定时任务才会执行。

CI 已恢复真实测试与生产构建，目录改为 `api`、`web`。PR 与 dev 执行检查，main 检查通过后延续既有镜像与 GitHub Pages 发布流程。Pages 是静态副本，自有域名的 API 与公开 HTML 仍由服务器和 Nginx 提供。

## 上线验收

1. 旧任务、正文、结果和公开链接仍在；迁移脚本重复运行不产生重复历史。
2. 重跑后有两条运行记录，旧记录及各格式导出不变。
3. 试跑与正式提交产生独立任务，复制配置不修改原任务。
4. 配置近期计划，确认调度服务在线，在计划时刻后约 30 秒产生新运行；暂停后不再触发。
5. 运行未结束时下一期显示跳过记录，不重叠执行；Worker 恢复后待执行消息只实际执行一次。
6. 字段错误显示原因，可通过正文复用修正；失败页面重试不重新处理成功页面。
7. 两个普通账号互不可见任务、运行、模板和计划；只读账号无法提交运行、修改计划或模板，普通账号没有用户管理入口。

自动化测试主要使用 SQLite 和本地 HTTP 站点。生产 PostgreSQL/Redis/Celery 联调、1000 条任务下的性能基线和实际服务器部署需在上线环境完成。
